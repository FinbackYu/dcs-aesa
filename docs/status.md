**实飞调试四连环（关键教训，勿重蹈）**：
1. 接收器写文件必须**行缓冲**（buffering=1）。
2. **`LuaExportActivityNextEvent` 在用户工具链下任务加载完成后被 DCS 停调**——采样必须用 **`LuaExportAfterNextFrame` 每帧回调自限频**驱动。
3. 大任务必须**整帧合并单次 send**。
4. 排查利器是**诊断日志**（`Saved Games\DCS\Scripts\AESA\export_diag.log`）。

## 4. 环境备忘

- DCS 安装目录：`<DCS>`（2.9.29，允许经部署脚本写入但本阶段未动过它）。
- 用户实际用 **DCS 稳定版**（openbeta 的日志停在 2023，不用）。
- DCS 启动卡死（edWebViewB）与本项目无关，已用日志证实；重试/Steam 校验可解。
- **DCS 闪退（2026-09-27 夜 5 次）**：全部 0xC0000005；edCore.dll@0x7114×2（启动期，我们脚本未运行）、ntdll.dll@0xcb776×3（20:13 启动期【注入已卸载】/ 21:49 任务重启 / 22:18 飞行中 45s）。同偏移=同一确定性引擎 bug；与我们的流量不相关（10 万行会话平安、3 万行崩）。结论：引擎自身问题；建议 Steam 校验 + 清 Saved Games 着色器缓存；A/B（卸载注入复测）邀约仍有效。
- **启动崩溃复发（2026-10-15 夜，fc_probe 部署当晚）**：同一签名 edCore.dll@0x7114 + ntdll 0xC0000005，全部发生在 webview 初始化阶段、探针 hook 加载之前（fc_native.log 无记录=探针不在场），与探针无关。当晚时间线：22:5x 两次无头冒烟（kill -9 收尾，可能加剧缓存损坏，今后一律优雅退出）→ 23:17 起多次启动失败 → 改名 fxo/metashaders2（`.bak-fc`）后 23:33 成功一次（正常游玩 23:41-23:45，探针 7/7 钩子工作、退出干净）→ 23:46 又崩 → 23:52 触发真正 Steam 校验（URI 首次触发无效，需确认 `Verifying Installed` 出现）。launcher.sqlite3 完整性检查通过（九月曾坏过一次，`.bad-20260929`）。教训：对 DCS 进程只用温和终止；失败会话不必然损坏缓存，但缓存改名是有效的一线手段。
- **根因查明（2026-10-16 晚）**：崩溃真凶是**安全软件实时防护注入**——它在 edWebViewBrowser（CEF 浏览器组件）初始化时注入/拦截导致 DCS 以 0xC0000005 崩在同偏移；禁用该防护服务后启动器立即恢复。这很可能也是 2026-09-27 系列崩溃的同一根因（同签名、同 webview 场景）。反复启动/强杀 DCS（无头测试期间）会提高安全软件拦截级别，是"越试越坏"的解释。建议：把 DCS 安装目录、`Saved Games\DCS` 与项目工作区加入安全软件白名单后按需恢复防护。
- 录制数据在 `recordings/`（gitignored，本机数据）；flight3-final.aesarec 含 168s 完整会话（回放/演示标准素材）。
