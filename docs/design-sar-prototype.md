# 任务内 SAR 小切片原型设计

- 状态：historical（2026-10-18 归档）

本步采用独立 Export 插件 + 本机 Node.js 接收/计算/显示；不更改既有空空雷达通道。TCP 3592 采集及固定格式命令，HTTP 3593 外部页面，均仅监听 127.0.0.1。不在座舱中显示，不调用闭源雷达设备。

流程：探测 terrain.GetHeight 与 LoGetAltitude → 用户选左右 45°、地距 → 固定 128 m 场景，逐帧采集 17×17 高程 → 采集 2 s 实际平台位置 → 基于固定散射点假设合成带相位的距离压缩回波 → 反投影至高程表面 → 显示归一化功率。采样不足、断线、模型时间回退、地形失败均中止，不补造轨迹/地形。位置传输保留足够小数，采样最多 60 Hz，地形切片查询每帧 17 次，遇到每秒接口探测额外查询机下高度一次。

第一版仅自动使用官方脚本有调用先例的 terrain.GetHeight(x,z)。LoGetAltitude(x,z) 官方注释含义有歧义，保留运行时探测数值，不据此自动生成地形。与机下 ASL−AGL 比较仅为诊断，不能单独证明任意坐标语义。若 Export 内无法加载 terrain，则明确报告不可用，后续再针对实际接口证据选择 mission/GUI 桥接；不启用 unsafe API、不取消任务沙箱。

波长 3 cm、带宽 75 MHz、固定随机相位等为项目假设。首版各高程网格顶点为各向同性散射点；2026-10-01 更新为世界地面单元内固定随机分布的表面样本、默认 1 m 单元面积加权，仍按局部坡面入射余弦近似。默认 Hann 距离/孔径加窗，提供矩形窗重算；详见 [表面散射与质量检查](sar-surface-quality.md)。无真实材质、建筑网格、目标散射模型、阴影、噪声、天线方向图、辐射定标。8 m 地形间隔限制场景表示，当前默认 129×129 输出格只表示插值/聚焦网格，不能据此宣称 1 m 地物识别能力。

采用 worker 计算以免堵塞 HTTP/采集。输入文件包含原始高程与轨迹，保存在 recordings/（忽略），支持同一算法离线重算。demo 只能显式启动，并永久标记合成数据，不能代替 DCS 实飞验证。

开发部署使用独立 AESA SAR 标记块、Scripts/AESA-SAR 路径和 manifest，Lua 5.1 编译先行，保留既有 Export.lua 字节与其他插件。未知同名文件/修改后的本插件文件拒绝覆盖；卸载只移除自己的块及哈希核验文件，备份留存。本阶段无发布包。

2026-10-01 增加按 F10 经纬度选区：`CAPTURE_GEO,id,latitude,longitude` 与原 `CAPTURE,id,side,range` 并存。Export 在执行时调用官方经纬度转换函数，按本机到固定中心的视线确定切片基底，限制地距 1–50 km。`STATUS` 追加可选的转换能力位，接收端仍接受旧六字段状态，旧插件不允许坐标采集；`TARGET,id,latitude,longitude,ground_range,relative_track_degrees` 确认中心，坐标采集完成前必须收到且与请求一致。确认信息随输入文件保存，服务 `/state` 暴露给页面。此步骤仅控制地形切片位置，未接入建筑数据，不代表建筑成像已实现。

同日增加服务端连续循环：`POST /continuous/start` 设置 side/range/window/record，`POST /continuous/stop` 取消采集并停止追加；`GET /state` 返回运行标志、完成数、失败数及等待原因。先采集后计算，worker 退出且无 job 才可继续，成功后间隔 500 ms，错误后间隔 2 s，连续三次错误停止。状态超时/断线等待恢复，不算作连续失败。循环使用既有 CAPTURE 命令，无 Export 源码变更。连续默认不落盘；保留最后完成图像/中心，新的采集目标另列 captureTarget，避免旧图中心与新目标混用。停止中的 worker 可完成，但不会再创建采集；重算不计作新采集。该循环减少点击，不保证无缝区域覆盖或增加建筑输入。

同日增加 processing quality=standard/fine（75/150 MHz、129²/257²）与 fast 快速测试档（输出格减半、散射单元加倍、脉冲过采样 2.5→1.5，明确标注降低过采样可能混叠），参数是项目波形假设；同一地形/轨迹按选择重新生成回波再聚焦。地形输入及 Export 协议保持不变。连续配置保存 quality/window，GUI 显示对比度独立于计算。服务提供只读 /scene。

同日增加 F10 窗口/同区高程/SAR 三栏。窗口由用户在浏览器共享弹窗中选择，仅本地视频播放，无音频/录制/上传；F10 不离屏、不自动定位或配准。/state 的 reference 与已显示图像绑定到 displayedScene，不混用下一张 lastScene；高程和 SAR 同基底并联动十字线。/snapshot 原子返回已显示图像和对应输入，--restore-display 可恢复带 scene 的快照，校验几何、来源/范围/中心并保留时间；旧图像快照无输入时仍禁止重算和高程参考。详见[地图与地形接口](dcs-map-terrain-interfaces.md)。

2026-10-08 成像改为 worker 线程池并行，不降低任何精度。回波合成按脉冲分块、反投影按像素行分块：每个脉冲从零距离单元开始并只写自己那一段，每个像素在自己的循环里累加全部脉冲，分块只改变任务分配、不改变求和顺序，因此并行结果与单线程逐位相同（512 m 与 128 m 实机录制逐像素比较 0 处差异）。池大小 = min(逻辑核数−1, 12)：本机 20 逻辑核 = 8 P 核带超线程 + 4 E 核，512 m 标准档在 1/2/4/8/12/19 worker 下为 54.8/29.9/16.3/9.4/7.1/7.8 s，超过物理核数只增加启动与内存流量，故设上限；`createService({workers})` 可覆盖。块数由估算工作量（散射点×脉冲×每散射点距离单元 + 像素×脉冲）决定，估算低于 800 ms 时保留原单 worker 路径，每个 worker 至少分到 250 ms 工作量（队伍固定开销实测约 250 ms）。散射点生成、几何/权重规划与峰值归一化仍在单线程完成（约 20 ms）。服务层语义不变：`job` 取代原 `worker` 变量作忙标志，同一时刻只算一张图，terminate() 终止整队，worker 异常退出以 promise 失败上报，连续采集循环不会因此卡住；`/state` 增加 `imaging:{mode,workers}` 供观察。
